The question that most tested my orchestrator was the combined question about the number of active projects and what the onboarding process says about a new consultant’s first week (test 5, and the same question I invoked on Lambda). Routing was correct, since the classifier sent it to both agents, and validation was correct, since the SQL passed. The weakness was synthesis. Each agent answered accurately within its own scope, but the synthesis step added a long “What Could Not Be Answered” section, noting that the SQL Agent had no onboarding data and that the documents lacked a full first-week breakdown. Nothing in it was false, but it was noise that no single agent would have produced. Test 7, the request to delete overdue invoices, showed the validation layer working: the router sent it to the SQL agent, Claude generated a destructive statement, and the validator marked it BLOCKED before it reached the database. In my cost table, retrieval answer generation used the most tokens (about 8,200 of roughly 15,000 total) because each call sends five document chunks as context, and synthesis was a distant second. This suggests multi-agent systems are most fragile at the seams: the handoffs, the combining step, and the cost of repeatedly passing context between agents. A single well-scoped agent has no handoff to get wrong. To fix this I would tighten the synthesis prompt to omit unanswerable sub-parts unless the question asks for them, and reduce the retrieval chunks to cut cost.
